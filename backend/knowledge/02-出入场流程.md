# 车辆入场与离场流程

## 入场流程

1. **车牌获取**：支持三种方式——手动输入车牌、上传图片识别、前端摄像头抓拍识别。
2. **黑名单校验**：车牌命中黑名单（且状态为启用）时，入场被拒绝，接口返回 403，并在操作日志中记录 block 操作。
3. **重复入场校验**：同一车牌若已有 status 为 parked 的在场记录，拒绝再次入场，返回 400。
4. **车位校验**：可用车位为 0 时拒绝入场，返回 400。
5. **预约联动**：若该车牌存在 pending 且当前时间处于预约时段内的预约，入场时优先放行，预约状态变为 arrived，备注写入预约时段。
6. **月租标记**：车牌是有效期内的月租车辆时，备注追加「月租车辆」。
7. **写库**：新增停车记录，状态 parked，可用车位减 1，并写入操作日志。

## 离场流程

1. **查找在场记录**：按车牌查找 status 为 parked 的最新记录，找不到返回 404。
2. **计算时长与费用**：按入场时间到当前时间计算分钟数，再按计费规则计算费用；月租车辆费用直接为 0。
3. **费用预览**：离场前可调用 exit-preview 接口预览时长与费用，不修改数据。
4. **结算**：写入离场时间、时长、费用，状态改为 exited；费用大于 0 时支付状态为 unpaid，否则为 free。
5. **释放车位**：可用车位加 1，且不超过总车位数。
6. **支付**：调用支付接口把 unpaid 改为 paid；重复支付或对 free 记录支付都会被拒绝。

## 关键约束

- 入场与离场必须在同一车牌下配对，不允许无记录离场。
- 车位数量在入场时减 1、离场时加 1，保证总车位与可用车位一致。
- 识别失败时必须允许手动录入，不能阻塞主业务流程。
