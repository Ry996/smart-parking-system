# 黑名单与异常处理规则

## 黑名单

黑名单记录在 blacklist 表中，包含车牌号、拉黑原因、欠费金额、是否启用与创建时间。
车牌号唯一，重复添加同一车牌会被拒绝。

黑名单用于拦截欠费、逃费、恶意占位等车辆：

- 车辆入场时，若车牌命中启用中的黑名单记录，入场被拒绝，接口返回 403，
  提示信息包含拉黑原因。
- 管理员可以修改拉黑原因与欠费金额，也可以解除黑名单（删除记录）。
- 解除后车辆可正常入场。

## 操作日志

系统把所有关键操作写入操作日志表 operation_logs，字段包括操作人、操作类型、操作对象、
详情、客户端 IP 与时间。记录的操作类型包括：login（登录成功）、login_fail（登录失败）、
enter（入场）、exit（离场）、pay（支付）、block（黑名单拦截）、create、update、delete、
export（导出）等。

管理员可在操作日志页面按操作人、操作类型和日期范围筛选审计记录。

## 异常与兜底

- 车牌识别失败时，前端改用人工输入车牌完成入场或离场，业务不中断。
- 图片无法读取、识别结果格式不可靠或置信度过低时，接口返回 422 并提示重新拍摄或手动录入。
- 依赖 OpenCV 或 HyperLPR3 不可用时，系统不影响启动，可开启模拟识别模式（LPR_MOCK_MODE）
  继续演示业务流程。
- 大模型服务不可用时，AI 运营建议自动降级为本地规则生成，并在返回结果中用 provider 字段标识。
